# Packaging: AppImage for SteamOS

The main download is a single self-contained **AppImage**:
`dist/Simple_ROM_Organiser-<version>-x86_64.AppImage` (about 18 MB).

It contains its own Python (a [python-build-standalone](https://github.com/astral-sh/python-build-standalone)
CPython 3.13, "install_only_stripped") and the `romorg` package. It does **not** use the host's Python. It is
built with [appimagetool](https://github.com/AppImage/appimagetool) and the static type-2 runtime, so at run
time it only needs `fusermount`, which SteamOS has. It does not need `libfuse2`.

A `.pyz` zipapp (`dist/simple-rom-organiser.pyz`) is still available as a secondary artifact. It needs the
host's `python3` (3.11+).

## Build

```sh
packaging/build_appimage.sh          # -> dist/Simple_ROM_Organiser-<version>-x86_64.AppImage
packaging/smoke_test.sh              # start it with a minimal env, check / and /api/status, POST /api/quit
packaging/build_pyz.sh               # secondary: dist/simple-rom-organiser.pyz
```

- Needs `bash`, `curl`, `tar` and `sha256sum`. The build itself doesn't need Python or FUSE: appimagetool is
  extracted once and then run from that copy.
- The version comes from `romorg/__init__.py` (`__version__`).
- Downloads are cached in `packaging/.cache/` (gitignored). Later builds reuse the cache and build offline.
  - **Python:** the latest `cpython-3.13.*-x86_64-unknown-linux-gnu-install_only_stripped.tar.gz`, found
    through the GitHub releases API. The script checks it against the sha256 digest the API reports. If the
    API can't be reached, it uses the newest tarball already in the cache.
  - **Tools:** `appimagetool-x86_64.AppImage` and `runtime-x86_64` (type2-runtime), both from the continuous
    channel.
- Staging happens in `build/appimage/AppDir`, which is deleted and rebuilt on every run.
- Before packing, the script checks that the bundled interpreter can import the app and its stdlib
  dependencies (`sqlite3`, `ssl`, `zlib`, …) and can see `romorg/static/index.html`.
- Options, set as environment variables:

  | Variable | Effect |
  |---|---|
  | `PY_SERIES=3.12` | Bundle the 3.12 series instead of 3.13. |
  | `PBS_TARBALL=/path/to.tar.gz` | Use a local Python tarball. |
  | `PRECOMPILE=0` | Ship `.py` sources only (about 15 MB instead of 18 MB, but startup takes ~0.6 s instead of ~0.1 s). |
  | `REFRESH_TOOLS=1` | Download appimagetool and the runtime again. |
  | `ROMORG_CACHE=dir` | Use a different cache directory. |

### What is removed from the bundled Python

These parts aren't needed at run time, so the build deletes them:

- tkinter, Tcl/Tk, IDLE and turtledemo
- `test/` and other test directories
- ensurepip and pip
- lib2to3 and pydoc_data
- headers, `config-*`, pkgconfig, man pages and terminfo
- the shared `libpython*.so`. The `python3` binary is statically linked; the shared library is only used
  for embedding.

The script also deletes any old `__pycache__`. With `PRECOMPILE=1` (the default) it then compiles fresh
`.pyc` files with `--invalidation-mode unchecked-hash`, because the image is read-only.

Result: the AppDir is 55 MB uncompressed and the AppImage is 18 MB.

### AppDir layout

```
AppRun                               sh: exec "$APPDIR/usr/python/bin/python3" -I -B -u -m romorg "$@"
simple-rom-organiser.desktop         Categories=Utility;Game;  Terminal=false
simple-rom-organiser.png, .DirIcon   256x256 floppy icon (generated by packaging/make_icon.py, stdlib only)
usr/python/                          relocatable CPython; romorg lives in lib/python3.13/site-packages/romorg
usr/share/icons/hicolor/{256x256,scalable}/apps/simple-rom-organiser.{png,svg}
usr/share/metainfo/simple-rom-organiser.appdata.xml
```

`AppRun` does the following before starting Python:

- Clears `PYTHONHOME` and `PYTHONPATH`, and runs Python with `-I` (isolated mode), so host Python settings
  can't leak in.
- Points `SSL_CERT_FILE` at the system CA bundle if `/etc/ssl/cert.pem` is missing (SteamOS has it), so DAT
  downloads over HTTPS work on other distros too.
- When there is no terminal, appends all output to `$XDG_STATE_HOME/simple-rom-organiser/app.log`
  (default `~/.local/state/...`) and rotates it at 1 MiB. Set `ROMORG_LOG=1` to log even from a terminal.

## Install on the Steam Deck (Desktop Mode)

```sh
packaging/install.sh                 # newest AppImage from dist/ (builds one if there is none)
packaging/install.sh path/to/Simple_ROM_Organiser-0.1.0-x86_64.AppImage
packaging/install.sh --rebuild       # rebuild first
packaging/install.sh --pyz           # install the secondary .pyz in ~/.local/bin instead
packaging/install.sh --uninstall     # remove the app, menu entry and icon (DATs/settings are kept)
```

`install.sh` only writes under `$HOME`, so SteamOS's read-only root filesystem isn't a problem. It installs:

- `~/Applications/Simple_ROM_Organiser.AppImage`, executable, with the same file name for every version
- `~/.local/share/applications/simple-rom-organiser.desktop`, with an absolute `Exec` path
- `~/.local/share/icons/hicolor/256x256/apps/simple-rom-organiser.png` (and a scalable SVG)

You can also just download the AppImage, `chmod +x` it, and double-click it in Dolphin.

## Running

- Start it from the application menu, or double-click the AppImage. It starts a local server on
  `127.0.0.1` with a random port and opens the default browser using `webbrowser` / `xdg-open`.
- **Quitting:** there is no terminal window, so use the **Quit** button in the top bar of the UI
  (`POST /api/quit`). Closing the browser tab does *not* stop the server. Killing the process also stops it
  cleanly, because `AppRun` uses `exec`, so the Python server is the AppImage's own process and handles
  SIGTERM. The FUSE mount then goes away. Examples: `pkill -f romorg`, or stopping it in Steam.
- From a terminal: `./Simple_ROM_Organiser-*.AppImage [--port N] [--no-browser] [--no-update] [--verbose]`.
  Output goes to the terminal.
- **Without FUSE** (containers, some sandboxes): add `--appimage-extract-and-run`, or set
  `APPIMAGE_EXTRACT_AND_RUN=1`.
- DATs, the hash cache and settings live in `~/.local/share/simple-rom-organiser/`. They are kept when you
  uninstall. TOSEC DATs are in `dats/`, the No-Intro DATs in `nointro/` (a separate folder, so a TOSEC update,
  which swaps `dats/` as a whole, never removes them).
- **Network access** is only used to keep the DATs current, automatically and in the background at
  every start: the TOSEC pack from `www.tosecdev.org` (about 100 MB, downloaded only when the newest
  release date differs from the installed one) and the four No-Intro DATs (GBA, N64, NES, SNES) from
  `raw.githubusercontent.com` (the libretro-database mirror, `metadat/no-intro/`; only changed files, via
  ETag). No GitHub API calls are made. Offline, scanning and organising work with the DATs already
  installed. `--no-update` (or `ROMORG_OFFLINE=1`) switches the automatic update off; the
  *Check for updates* button in the UI repeats it on demand. `updates.json` in the data folder records
  the last check.
- A TOSEC update installs the new `dats/` folder and `release.json` in one swap, and each No-Intro DAT
  is replaced atomically, so killing the app mid-update (Steam stop, shutdown) never leaves half-installed DATs.

## Steam / Game Mode

**Desktop Mode is the main target.** You can add the app to Steam:

1. In Desktop Mode, open Steam and choose *Games → Add a Non-Steam Game to My Library…*
2. Pick *Simple ROM Organiser*. If it isn't listed, click *Browse* and select
   `~/Applications/Simple_ROM_Organiser.AppImage`.

In Game Mode the server starts, but the browser window it opens may not appear on top of the gamescope
session, or may not appear at all. If that happens:

- Switch to Desktop Mode, or
- Open a browser yourself and go to the URL shown in `~/.local/state/simple-rom-organiser/app.log`. To keep
  the address fixed, set the launch options to `--port 8765`.

Stopping the game in Steam ends the server.

## Tests

`tests/test_packaging.py` checks the following:

- The icon generator produces a valid PNG (signature, chunk CRCs, size).
- The SVG and metainfo files are valid XML.
- The `.desktop` keys are correct.
- `AppRun` is executable and uses `exec` and `-I`.
- The shell scripts pass `bash -n`.
- `.gitignore` has the required entries.

Checks on `dist/*.AppImage` (ELF + `AI\x02` magic) and `build/appimage/AppDir` (bundled Python present,
stdlib trimmed, `romorg/static` included) are skipped until `packaging/build_appimage.sh` has been run.

## Windows

Two builds, both 64-bit and needing no install or admin rights:

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build_windows_exe.ps1   # dist\Simple_ROM_Organiser-<version>-win64.exe
powershell -ExecutionPolicy Bypass -File packaging\build_windows.ps1       # dist\Simple_ROM_Organiser-<version>-win64.zip
```

- **Single `.exe` (main download, about 9 MB):** built with PyInstaller `--onefile --windowed` from
  `packaging/windows_entry.py`. With no console, output goes to `%LOCALAPPDATA%\simple-rom-organiser\app.log`
  (rotated at 1 MiB; set `ROMORG_LOG=1` to force it). It unpacks itself to a temp folder on every start, so
  startup takes a second or two. Unsigned one-file executables are sometimes flagged by antivirus tools.
  The build needs Python 3.11+ with `pip`; it installs PyInstaller if missing, then starts the finished exe
  and checks that the UI answers.
- **Zip (fallback):** the official embeddable CPython plus the `romorg` sources, started by
  `Simple ROM Organiser.vbs`. Nothing is unpacked at run time and it never trips antivirus.
- Quit with the Quit button in the UI. Data and settings are in `%LOCALAPPDATA%\simple-rom-organiser`.
- The folder dialog is a native Windows dialog opened through PowerShell.

### Windows: chdman, 7-Zip and speed

- **chdman** is optional but much faster than the built-in Python CHD reader (above all for FLAC audio tracks,
  which the Python reader decodes at only 1-2 MB/s per process). The app looks for `chdman.exe` on `PATH`, next to
  the app (`.exe` or `.zip` folder), and in common folders (Program Files, `%LOCALAPPDATA%\MAME`, RetroArch, Scoop,
  `C:\mame`). Or set `ROMORG_CHDMAN` / the `chdman_path` setting. It ships in the MAME download.
  Drop `chdman.exe` beside `Simple_ROM_Organiser-*.exe` and it is picked up.
- **7-Zip** (`7z.exe`, for `.7z` / `.rar`) is found on `PATH`, in `C:\Program Files\7-Zip` and next to the app.
- Without chdman, CHD hashing uses a pool of worker processes (the frozen exe starts itself with `--chd-worker`),
  so several tracks decode in parallel. Loose files are hashed by a small thread pool (`scanner.HASH_THREADS`).
- External tools run with `CREATE_NO_WINDOW`, so no console window flashes from the windowed exe.
- Very long paths (over 260 characters) need the Windows `LongPathsEnabled` setting.
- **Which engine hashes a CHD** (measured on a 20-thread PC, MB/s of disc data): `chdman` extracts one disc at a
  time (~54 data, ~63 DVD, ~100 CD audio) into scratch space and the result is hashed again, while the built-in
  reader decodes data / DVD hunks in parallel across the worker pool (~155 / ~170) but FLAC audio slowly (~15).
  With `chdman` present the app therefore chooses per disc (`discsys.prefer_chdman`): the built-in reader for data
  and DVD CHDs, `chdman` for audio-heavy CDs and for codecs the reader lacks (zstd, huff, ...). `engine = "chdman"`
  or `"python"` forces one. Verifying a freshly converted CHD follows the same rule. Creating a CHD is always
  `chdman createcd/createdvd` with its own (multi-threaded) defaults.
- **`.7z` archives are read in Python** (`romorg/sevenzip.py`: LZMA / LZMA2 / stored, header and members), so
  listing one costs ~0.1 ms instead of an ~86 ms `7z.exe` launch, and no 7-Zip is needed for them. BCJ / PPMd /
  BZip2 / encrypted archives and `.rar` still use `7z.exe`; big members are also extracted by `7z.exe` when it is
  installed (it decodes ~2x faster than Python). Zip members are matched from the CRC in the zip directory, so
  nothing is decompressed for a scan.
- The exe build runs `--selftest` with the name of every `romorg` module: the server imports modules by name, which
  PyInstaller cannot see, so `--collect-submodules romorg` is required and checked.
